# Petra k6 API load tests

This suite targets the real Petra API routes currently mounted by `backend/app.js`.

## Routes covered

- `GET /health`
- `POST /api/auth/login`
- `GET /api/auth/me`
- `GET /api/students/`
- `GET /api/finance/fees`
- `GET /api/finance/payments`

The authenticated flow uses Petra's normal cookie session behavior. No production payment, admission, student creation, or other mutating workflow is generated by the load test.

## Why these endpoints

They exercise the main request path plus authentication, tenant-scoped student reads, and tenant-scoped finance reads. This gives a useful baseline for API, PostgreSQL, Redis/rate-limiter, and session behavior before adding heavier workflow-specific tests.

## Requirements

Install k6 locally from the official Grafana k6 documentation, then run the backend against a dedicated test/staging database.

Required environment variables for authenticated tests:

```text
BASE_URL=http://localhost:5000
PETRA_TEST_EMAIL=<dedicated test principal email>
PETRA_TEST_PASSWORD=<dedicated test principal password>
ORIGIN_SECRET=<only if your environment requires x-origin-secret>
```

Do not put credentials, origin secrets, Paystack keys, JWT keys, or database passwords in this repository.

## Smoke/load test

```bash
BASE_URL=http://localhost:5000 \
PETRA_TEST_EMAIL='test@example.com' \
PETRA_TEST_PASSWORD='TestPassword1!' \
k6 run tests/k6/petra-api.js
```

Customize the basic load with `VUS`, `DURATION`, and `THINK_TIME`.

## Progressive stress test

```bash
BASE_URL=http://localhost:5000 \
PETRA_TEST_EMAIL='test@example.com' \
PETRA_TEST_PASSWORD='TestPassword1!' \
k6 run tests/k6/petra-stress.js
```

The checked-in profile ramps through 10, 50, 100, 250, and 500 virtual users. Increase the ceiling only after observing PostgreSQL connections, CPU, RAM, Redis, and application error rates.

## Pass/fail criteria

The suite uses k6 thresholds for request failure rate, p95/p99 latency, and checks. k6 treats threshold breaches as test failures, making the suite suitable for later CI automation.

These are initial engineering gates, not a claim that Petra's final production SLOs are 2% errors / 1.5-3 seconds latency. Tune them after baseline measurements.

## Safety

Run stress tests against a dedicated staging/test environment. Do not point the 250/500-VU profile at a production school database or real payment endpoints.
