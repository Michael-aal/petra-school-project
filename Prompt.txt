5. IMPORTANT: APPLICANT CODE VS STUDENT CODE

There are TWO different codes.

Applicant Code

Generated when the admission application is submitted.

Used for:

- Applicant identification
- Entrance exam
- TestPortal candidate/exam relationship
- Exam result retrieval

Student Code

Generated ONLY after:

Applicant passes
↓
Admission is approved/confirmed
↓
Student record is created

The Student Code is then used for:

- Student identification
- Parent dashboard
- Student dashboard
- School fees
- Payment
- Student records

NEVER treat these two codes as the same thing.

Do not generate a Student Code simply because an application was submitted.

Do not generate a Student Code for a failed applicant.

20. PAYSTACK SECURITY

Never trust the frontend to declare a payment successful.

The backend MUST verify the transaction with Paystack before marking it successful.

Prevent:

- Fake successful-payment requests
- Duplicate payments
- Duplicate payment records
- Paying another student's fees
- Updating the wrong student's balance
- Manually changing payment status from the frontend
- Reusing transaction references

Every payment should have a unique transaction/reference.

Use clear payment statuses such as:

pending
successful
failed
cancelled

Adapt these to the existing Petra database if equivalent statuses already exist.
